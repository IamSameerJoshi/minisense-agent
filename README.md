## MiniSense: Survey Analysis & Intelligence Agent

MiniSense is an agentic, document-grounded survey intelligence system for
GreenLeaf Bistro. It analyzes large-scale customer feedback by separating
deterministic statistical calculations from semantic policy retrieval, then
combines both outputs into grounded executive insights without asking an LLM
to perform arithmetic over raw survey records.

The repository includes a reproducible synthetic dataset containing 60,000
survey responses from April 1 through May 31, 2026.

## System Architecture

MiniSense uses a two-level agent pipeline connected by typed Pydantic schemas:

```text
													  User Question
														   |
												+------------v------------+
												| Orchestrator Agent      |
												| Planner + Synthesizer   |
												+------------+------------+
													DataTaskSpec | RAGTaskSpec
														|              |
												+---------v--+    +------v-----+
												| DataAgent  |    | RAGAgent    |
												+---------+--+    +------+------+
														|              |
												Polars metrics    ChromaDB search
														|              |
												DataAgentResult  RAGAgentResult
														\              /
														 +------v------+
														 | Executive   |
														 | Narrative   |
														 | Synthesis   |
														 +-------------+
```

### Components

- **Orchestrator Agent** (`src/agents/orchestrator.py`) uses Gemini to plan
	execution, validates `DataTaskSpec` and `RAGTaskSpec`, routes both tasks,
	and synthesizes the final narrative.
- **DataAgent** (`src/agents/data_agent.py`) runs deterministic Polars
	calculations through `src/tools/metrics.py`. Raw survey arrays are not sent
	to the LLM.
- **RAGAgent** (`src/agents/rag_agent.py`) queries the persistent ChromaDB
	index for business policies, service targets, and operating procedures.
- **Schemas** (`src/schemas.py`) define the task and result contracts between
	the orchestrator and its sub-agents.

## Capabilities

- Inclusive date-range and business-level filtering
- Average rating, CSAT percentage, response count, rating distribution, and
	phrase-based theme analysis
- Semantic search over GreenLeaf Bistro's FAQ
- Grounded comparisons against documented business targets
- Structured CLI output containing narrative, metrics, and retrieved context
- Persistent local ChromaDB storage for repeatable retrieval

## Setup

Requirements:

- Python 3.10 or newer
- A Gemini API key
- Network access on first ChromaDB embedding-model initialization

```bash
git clone https://github.com/IamSameerJoshi/minisense-agent.git
cd minisense-agent

python3 -m venv .venv
# On Windows: python -m venv .venv
source .venv/bin/activate
# On Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
cp .env.example .env
# On Windows: copy .env.example .env
```

Set the API key in `.env`:

```dotenv
GEMINI_API_KEY=your_gemini_api_key_here
```

### Generate survey responses (Appendix A)

```bash
python data/generate_surveys.py
```

### Ingest and chunk FAQ document into ChromaDB (Part 2)

```bash
python src/rag/ingest.py
```

Ingestion splits each `Q:`/`A:` entry in `data/product_faq.txt` into an atomic
chunk and recreates the `bistro_faq` collection using Chroma's default
sentence-transformer embedding function.

## Run the Agent

Run the default question:

```bash
python main.py
```

Ask a custom business question:

```bash
python main.py "What was our CSAT performance in May 2026, and how does it compare to our target?"
python main.py "What are the top customer complaints regarding wait times, and what is our escalation procedure?"
```

The CLI prints:

1. A concise executive narrative generated by Gemini.
2. Structured data metrics, including response count, score, distribution, and themes.
3. Retrieved FAQ chunks with IDs, relevance scores, and source text.

## Metric Semantics

The deterministic metrics tool applies inclusive `start_date` and `end_date`
filters and calculates:

- `average_rating`: mean rating on a 1-5 scale, rounded to two decimals
- `csat_score`: currently the same 1-5 average used by the FAQ comparison
- Satisfied-response percentage: the percentage of ratings that are 4 or 5,
	calculated internally by the metrics tool
- `rating_distribution`: counts for ratings 1 through 5
- `top_themes`: phrase-based counts for wait times, food quality, and cleanliness

The FAQ defines GreenLeaf Bistro's company-wide CSAT target as **4.5 or higher
on a 1-5 scale**. In the included synthetic data, May's observed CSAT is about
**3.27**, which is below the target and below the FAQ's **4.0** threshold for a
mandatory regional root-cause review.

## Tool Calling Example

The `DataAgent` demonstrates tool calling through a typed Python boundary:
`DataAgent.execute()` receives a validated `DataTaskSpec` and calls the
`compute_survey_metrics()` tool with its date and business filters. The tool
loads and filters the JSON data with Polars, computes the exact aggregates, and
returns a `DataAgentResult`. This keeps arithmetic and raw records outside the
LLM prompt; Gemini plans the call and narrates its typed result.

Retrieval is strongest when the query uses the FAQ's terminology. Queries that
refer indirectly to programs or delays may need a higher `top_k`, and
multi-intent questions can retrieve adjacent operational policies.

## Fine-Tuning Architecture Proposal

The current repository uses Gemini for planning and narrative synthesis. For a
production workload processing roughly 10,000 survey responses per day, a
specialized classifier could reduce inference cost and latency for the
discrete eight-class taxonomy, such as `Positive - Food Quality` and
`Negative - Wait Time`.

### Data strategy

- Curate 4,000-6,000 balanced labeled examples, with roughly 500-750 examples
	per class.
- Bootstrap labels with GPT-4o across rating tiers and response channels.
- Send ambiguous or low-confidence examples to human review.
- Reserve a human-audited validation set of 1,000 examples, or 125 per class.

### Model and training approach

- Use Llama 3.1 8B Instruct, or ModernBERT-Large when sub-15 ms classification
	latency is required.
- Use PEFT/LoRA with rank 16 and alpha 32 on attention and MLP projections.
	LoRA is preferable to full fine-tuning because it keeps the base model
	frozen, reduces GPU memory use, and produces a small swappable adapter.
	QLoRA is an alternative when GPU memory is tighter; full fine-tuning would
	be reserved for a substantially larger corpus and a stable taxonomy.
- Train with Hugging Face TRL or Axolotl, FlashAttention-2, and PyTorch FSDP.
- Start with AdamW, cosine scheduling, effective batch size 64, peak learning
	rate `2e-4`, and early stopping over three epochs.

### Evaluation and production gate

Track macro F1, per-class F1, Cohen's kappa, schema validation failures, and
p99 latency. Require at least 95% agreement with GPT-4o, zero schema failures,
macro F1 of at least 0.92, and a 48-hour shadow-mode run before cutover.

### Serving and future-proofing

Serve the adapter with vLLM on an AWS `g5.xlarge`, keeping the frontier model
as a fallback for low-confidence cases. Inject taxonomy classes dynamically
through schemas rather than hardcoding them in prompts, and monitor incoming
text for feature and embedding drift with two-sample Kolmogorov-Smirnov tests.
The training and serving interfaces should accept versioned input and output
schemas so taxonomy changes do not require rewriting the pipeline.

This section is a future design proposal; the repository does not currently
contain training, vLLM serving, or drift-monitoring code.

## Limitations

- The included survey data and FAQ are synthetic/demo inputs.
- Gemini API access is required for planning and narrative synthesis.
- Theme extraction is lightweight and phrase-based rather than a learned classifier.
- Retrieval quality depends on FAQ vocabulary and the selected `top_k`.
- Automated tests and the proposed fine-tuning pipeline are not yet included.
